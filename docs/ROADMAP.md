# Roadmap: beta to 1.0.0

From the first beta (0.3.0b1) to **1.0.0, software that can be published and
cited**: stable formats, validated methods, safe defaults, usable without the
developer, and ready for review as a software paper (JOSS) and, beyond it, a
methods paper. Milestones and their state also live in `docs/WORKPLAN.md`
(M9–M12); what each release shipped is in `docs/RELEASE_NOTES.md`.

## What 1.0.0 must be

- **Stable:** the pipeline, session and plugin specs frozen at 1.0 (JSON Schema,
  semver); after that only additive changes until 2.0, with a deprecation policy.
- **Validated:** every built-in strip compared with a reference implementation,
  with tolerances, in a validation report generated by CI; one published study
  replicated on real data.
- **Safe:** Sterile mode, an authenticated control channel, a supply-chain
  check in CI, deliberate handling of identifying data.
- **Usable:** templates, sample data, undo, a user guide site, a shortcut to
  start it.
- **Reviewable:** contributing guide, code of conduct, security policy, licence
  audit, DOI per release, a JOSS paper.

### M9: Fix and harden (0.3.0bN)

1. **Beta triage:** everything the manual release checks (`docs/TESTING.md`) and
   beta users turn up comes first.
2. **CI catches platform type errors:** a `mypy --platform win32` step in the lint
   job (the beta check found one only on Windows).
3. **Control-channel token:** the daemon writes a per-session token to a file only
   the user can read; ZeroMQ checks it (PLAIN, via ZAP) on the control and the
   display socket alike. CurveZMQ (encryption) replaces PLAIN when a remote GUI
   needs it.
4. **Supply chain:** pip-audit and CodeQL in CI, PyPI attestations (PEP 740), an
   SBOM attached to each release.
5. **Share-safe sessions:** an option that strips absolute paths, subject
   identifiers and EDF header fields from a session; a short de-identification
   guide for EDF and BIDS outputs.
6. **Pipelines never run code:** a test that loading a pipeline or session cannot
   start a custom script or plugin without the accepted notice.
7. **Feature units:** each feature window states its unit (one for every value,
   or one per entry along a dimension, e.g. specparam's measures; spec 0.2.19);
   the feature view and tables show them.
8. **Robustness:** a channel-layout change mid-stream no longer stops the LSL
   feature outlet; live recording to disk survives a crash (writes are flushed
   and the file stays readable).
9. **Project hygiene:** `SECURITY.md` (reporting and supported versions),
   `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, issue and PR templates.

### M10: Research workflows (0.4.0bN)

1. **Resample and channel-pick strips** (rule 8 already defines how a rate change
   maps indices). Decided: the pick strip keeps channels by type and by name and
   can drop bad ones; the resampler is a streamed polyphase FIR (one path, live
   and offline); events stay on the input's clock and readers map them by the
   exact ratio of the rates.
2. **Epoching and the events writer:** epochs around events on the Events rail,
   written as `.fif`/`.set` epoch files and BIDS derivatives; an events writer
   (`events.tsv`). Decided: epochs are a side rail (the epoched signal beside the
   chain), not a new port type.
3. **ERP view:** a tap on epochs shows the averaged ERP per condition, live
   (running average) and offline, with the channel and condition choices of the
   feature view.
4. **Bad segments:** amplitude, flat-line and jump thresholds write `BAD_` spans
   onto the Events rail; fits, epochs and writers honour them. Decided: using
   them is a parameter of each strip that could (off, or the span labels to
   honour), not automatic.
5. **XDF input** (pyxdf): LabRecorder files, a signal plus marker streams placed on
   the signal's sample index as live markers are.
6. **EEGLAB decompositions (4b):** a `.set` with `icaweights` starts the ICs rail at
   the Input strip; ICA rewrites it. Writing `.set` keeps the ICA solution and the
   ICLabel classification (`EEG.etc.ic_classification`).
7. **MNE interop:** a Python API, `meegxer.run(pipeline, raw) -> Raw | Epochs`, a thin
   layer over the batch scheduler (rule 4: no second code path); MNE ICA `.fif`
   read onto and written from the ICs rail.
8. **Batch at scale:** parallel workers for `--bids` runs and a per-subject HTML QC
   report (DESIGN §7 item 2).
9. **First run:** *New from template* (resting-state spectra, ERP, ICA cleaning,
   SSVEP BCI) and a sample-data download.
10. **Editing:** undo and redo for chain and parameter edits; keyboard shortcuts;
    plain-language reasons for a red strip.

### M11: Isolation and BCI (0.5.0bN)

1. **Sterile mode** (WORKPLAN M8 item 2): a processing-worker image with the
   built-in nodes; the whole chain in one container with `--network none` and
   read-only mounts; one hop per block; the *Sterilize* switch in the GUI and
   the CLI; delay measured with `tools/stability_test.py`; identical output to a
   local run.
2. **Plugin hardening:** CPU and memory limits for plugin containers; images
   pinned by digest in sessions; the plugin protocol and display decoders fuzzed.
3. **LDA classifier:** reads a feature rail, fits on labelled calibration, adds
   class events to the Events rail.
4. **Keyboard sink** (rule 9: only host sinks act): explicitly armed, rate-limited,
   with a visible stop; a "not a medical device" statement in the README and the
   About box.
5. **Octave/EEGLAB script tier:** `function EEG = process(EEG, ...)`, then live.
6. **Shortcut creation:** `meegxer-gui --create-shortcut` for the Windows Start
   menu and desktop, a `.desktop` file on Linux, an app launcher on macOS.

### M12: Freeze and validate (1.0.0rcN)

1. **Spec freeze 1.0:** pipeline, session and plugin specs at 1.0 with JSON Schema;
   the deprecation policy written down.
2. **Validation report** (generated in CI, published in the docs; feeds the
   paper): each built-in against its reference with stated tolerances. Filters
   against MNE and EEGLAB (`pop_eegfiltnew`); re-referencing and CSD against the
   CSD toolbox; specparam against the specparam library; ICLabel and pwelch
   against EEGLAB (concordance exists); connectivity against mne-connectivity;
   CSP against MNE; epoching and ERPs against MNE and ERPLAB.
3. **Real-data replication:** ERP CORE (Kappenman et al. 2021): reproduce
   selected ERP components against its published EEGLAB/ERPLAB pipeline and
   results; a resting-state OpenNeuro dataset for the spectral and ICA path.
4. **Interoperability tests:** FieldTrip (in Octave) reads MeegXer's `.set` and BIDS
   outputs; bids-validator passes on derivatives; HED tags in `events.tsv` pass
   through.
5. **Performance and soak:** the latency target of acceptance test 3 agreed and
   met; an 8-hour live run with no memory growth or dropped samples; the 16 ch /
   500 Hz online benchmark on a modest laptop.
6. **Reproducibility across systems:** the same session gives byte-identical
   output on Linux and Windows (acceptance test 4, cross-OS).
7. **Acceptance test 5 in CI:** Windows with Docker as a nightly or self-hosted
   job instead of a manual check; a coverage report with a floor.
8. **Docs site:** a user guide (MkDocs on GitHub Pages) with tutorials and
   screenshots; a strip reference generated from the manifests; accessibility
   (keyboard navigation, a high-contrast theme).
9. **Usability round:** 3–5 people from the lab, System Usability Scale, fixes
   before the last release candidate.
10. **Publication:** Zenodo DOI per release, a dependency licence audit (GPL-3.0
    compatibility, the ICLabel weights), the JOSS paper (statement of need,
    state of the field, validation summary); the methods paper drafted from the
    validation report and the replication.
